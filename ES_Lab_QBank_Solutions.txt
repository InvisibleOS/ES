Q1. Read data from memory and write data to memory     [ASM / .s] [SOFTWARE]
    Manual ref: Expt 1, Prog 3 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations vs manual:
  - Unused/dead code removed (VALU, R/T, register-offset load, etc.).
  - Post-indexed stores (STR Rx,[R4],#4) update the pointer for free, so no
    separate offsets/ADD instructions are needed.
  - ADR (PC-relative) used for source -> no literal-pool load.

        AREA    RWMEM, CODE, READONLY
        ENTRY
        ADR     R0, SRC             ; R0 -> source data in code memory
        LDR     R4, =RES            ; R4 -> destination in data memory (0x40000000)
        LDR     R1, [R0]            ; read WORD       -> R1 = 0xAABBCCDD
        LDRB    R2, [R0]            ; read BYTE       -> R2 = 0x000000DD
        LDRH    R3, [R0]            ; read HALF-WORD  -> R3 = 0x0000CCDD
        STR     R1, [R4], #4        ; write word,  then R4 = R4 + 4
        STRB    R2, [R4], #4        ; write byte,  then R4 = R4 + 4
        STRH    R3, [R4]            ; write half-word
STOP    B       STOP
SRC     DCD     0xAABBCCDD

        AREA    DATAMEM, DATA, READWRITE
RES     SPACE   12                  ; 3 words reserved at 0x40000000
        END

Result (memory window @ 0x40000000):
  0x40000000 = 0xAABBCCDD, 0x40000004 = 0xDD, 0x40000008 = 0xCCDD

Fastest alternative (pure block copy - 2 instructions move 3 words):
        ADR     R0, SRC
        LDR     R4, =RES
        LDMIA   R0, {R1-R3}         ; read 3 words in ONE instruction
        STMIA   R4, {R1-R3}         ; write 3 words in ONE instruction
STOP    B       STOP
SRC     DCD     0xAABBCCDD, 0xABCDEF78, 0x11223344

        BNE next

        END

Q3. Check whether the number is even or odd            [ASM / .s] [SOFTWARE]
    Manual ref: Expt 2, Prog 1 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations / fixes vs manual:
  - One ANDS tests the LSB directly and sets the Z flag (no shift into carry
    needed); R1 itself holds the answer (0 = EVEN, 1 = ODD).
  - MVNEQ #0 makes 0xFFFFFFFF without a literal-pool load.
  - BUG FIX: the manual's "MOVCS ... ; IF EVEN" is wrong - after LSR #1,
    Carry = LSB, so CS actually means ODD. This version is correct.
  - The manual's "MOV R0,#NUMBER" used an undefined symbol; here the number
    really is read from memory.

        AREA    EVENODD, CODE, READONLY
        ENTRY
        LDR     R0, NUM             ; read the number from memory
        ANDS    R1, R0, #1          ; R1 = LSB : 0 = EVEN, 1 = ODD  (Z=1 if EVEN)
        MVNEQ   R2, #0              ; EVEN -> R2 = 0xFFFFFFFF
        LDRNE   R2, =0x55555555     ; ODD  -> R2 = 0x55555555
        LDR     R3, =RES
        STR     R2, [R3]            ; result flag stored at 0x40000000
STOP    B       STOP
NUM     DCD     0x0000001B          ; number to test (27 -> ODD)

        AREA    DATAMEM, DATA, READWRITE
RES     DCD     0
        END

Result: NUM = 0x1B (odd)  -> R1 = 1, R2 = [0x40000000] = 0x55555555
        NUM = 0x1A (even) -> R1 = 0, R2 = [0x40000000] = 0xFFFFFFFF

Q5. Data transfer with shift/rotate                    [ASM / .s] [SOFTWARE]
    Manual ref: Expt 1, Prog 5 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations vs manual:
  - Every shift/rotate is done by the barrel shifter inside a single MOV.
  - ROL (not available on ARM) is done as ROR #(32-n)  -> answers the manual's
    "Can rotate left be used?" note.
  - MOVS on LSR captures bit0 into Carry so the RRX result is deterministic.
  - All 7 values (original + 6 results) written by ONE STMIA instead of
    separate stores.

        AREA    SHIFTROT, CODE, READONLY
        ENTRY
        LDR     R0, NUM             ; take the number from memory
        LDR     R8, =RES            ; R8 -> result block (0x40000000)
        MOV     R1, R0, LSL #2      ; LSL #2 : R0 * 4
        MOVS    R2, R0, LSR #1      ; LSR #1 : R0 / 2 (unsigned), C = bit0 of R0
        MOV     R3, R0, ASR #1      ; ASR #1 : R0 / 2 (signed, sign preserved)
        MOV     R4, R0, ROR #4      ; ROR #4 : rotate right by 4
        MOV     R5, R0, ROR #28     ; ROL #4 : rotate LEFT by 4 (= ROR #28)
        MOV     R6, R0, RRX         ; RRX    : rotate right 1 bit through Carry
        STMIA   R8, {R0-R6}         ; store original + 6 results, ONE instruction
STOP    B       STOP
NUM     DCD     0x8000001F

        AREA    DATAMEM, DATA, READWRITE
RES     SPACE   28                  ; 7 words at 0x40000000
        END

Result (from 0x40000000):
  0x8000001F (original), 0x0000007C (LSL#2), 0x4000000F (LSR#1),
  0xC000000F (ASR#1),    0xF8000001 (ROR#4), 0x000001F8 (ROL#4),
  0xC000000F (RRX, C=1)

Q7. Add two 16-bit numbers                             [ASM / .s] [SOFTWARE]
    Manual ref: Expt 3, Prog 2 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations vs manual:
  - ONE word load fetches BOTH 16-bit numbers (manual: 3 loads incl. MASK).
  - No MASK constant, no "MOV R0,#0", no AND instructions.
  - VALUE2 is extracted for free by the barrel shifter inside the ADD.
  - The 17th bit (carry) is preserved in bit16 of the result.

        AREA    ADD16, CODE, READONLY
        ENTRY
        LDR     R1, VALUES          ; R1 = 0x2222AAAA  (VALUE2:VALUE1)
        MOV     R2, R1, LSL #16     ; drop VALUE2 bits
        MOV     R2, R2, LSR #16     ; R2 = VALUE1 = 0x0000AAAA
        ADD     R0, R2, R1, LSR #16 ; R0 = VALUE1 + VALUE2
        LDR     R4, =RESULT
        STR     R0, [R4]            ; store result at 0x40000000
STOP    B       STOP
        ALIGN
VALUES  DCW     0xAAAA              ; VALUE1
        DCW     0x2222              ; VALUE2

        AREA    DATA2, DATA, READWRITE
RESULT  DCD     0
        END

Result: R0 = [0x40000000] = 0x0000CCCC

Q9. Arithmetic instructions: Addition, Subtraction...  [ASM / .s] [SOFTWARE]
    Manual ref: Expt 3, Prog 1 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations vs manual:
  - Both operands loaded with ONE LDMIA (manual: 2 separate LDRs).
  - Results kept in separate registers and written with ONE STMIA
    (manual: 7 separate STR instructions with write-back).
  - ADDS/SUBS set the Carry so ADC/SBC/RSC actually use a meaningful carry.
  - MVN added for a true bit complement (1's complement); BIC kept as in manual.

        AREA    ARITH, CODE, READONLY
        ENTRY
        ADR     R0, NUM1
        LDMIA   R0, {R1, R2}        ; R1 = NUM1, R2 = NUM2 (one instruction)
        LDR     R0, =RES            ; R0 -> result block (0x40000000)
        ADDS    R3, R1, R2          ; R3  = R1 + R2          (sets C)
        ADC     R4, R1, R2          ; R4  = R1 + R2 + C
        SUBS    R5, R1, R2          ; R5  = R1 - R2          (sets C = NOT borrow)
        SBC     R6, R1, R2          ; R6  = R1 - R2 + C - 1
        RSB     R7, R1, R2          ; R7  = R2 - R1
        RSC     R8, R1, R2          ; R8  = R2 - R1 + C - 1
        BIC     R9, R1, R2          ; R9  = R1 AND (NOT R2)  (bit clear)
        MVN     R10, R1             ; R10 = NOT R1           (bit complement)
        STMIA   R0, {R3-R10}        ; store all 8 results, ONE instruction
STOP    B       STOP
NUM1    DCD     0xF7654321
NUM2    DCD     0xF2345678

        AREA    DATAMEM, DATA, READWRITE
RES     SPACE   32                  ; 8 words at 0x40000000
        END

Result (from 0x40000000):
  ADD = 0xE9999999 (C=1)   ADC = 0xE999999A
  SUB = 0x0530ECA9 (C=1)   SBC = 0x0530ECA9
  RSB = 0xFACF1357         RSC = 0xFACF1357
  BIC = 0x05410101         MVN = 0x089ABCDE

Q15. Arithmetic instructions: Addition, Subtraction...
                                               (same as Q9) [ASM / .s] [SOFTWARE]
     Manual ref: Expt 3, Prog 1 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations vs manual: ONE LDMIA for operands, ONE STMIA for all 8 results,
ADDS/SUBS give meaningful carry to ADC/SBC/RSC, MVN added for 1's complement.

        AREA    ARITH, CODE, READONLY
        ENTRY
        ADR     R0, NUM1
        LDMIA   R0, {R1, R2}        ; R1 = NUM1, R2 = NUM2 (one instruction)
        LDR     R0, =RES            ; R0 -> result block (0x40000000)
        ADDS    R3, R1, R2          ; R3  = R1 + R2          (sets C)
        ADC     R4, R1, R2          ; R4  = R1 + R2 + C
        SUBS    R5, R1, R2          ; R5  = R1 - R2          (sets C = NOT borrow)
        SBC     R6, R1, R2          ; R6  = R1 - R2 + C - 1

Q19. Check whether the number is even or odd    (same as Q3) [ASM / .s] [SOFTWARE]
     Manual ref: Expt 2, Prog 1 - OPTIMISED
--------------------------------------------------------------------------------
Optimisations / fixes vs manual: one ANDS tests the LSB and sets Z; MVNEQ makes
0xFFFFFFFF without a literal load; fixes the manual's EVEN/ODD inversion
(after LSR #1, Carry = LSB, so CS = ODD, not EVEN).

        AREA    EVENODD, CODE, READONLY
        ENTRY
        LDR     R0, NUM             ; read the number from memory
        ANDS    R1, R0, #1          ; R1 = LSB : 0 = EVEN, 1 = ODD  (Z=1 if EVEN)
        MVNEQ   R2, #0              ; EVEN -> R2 = 0xFFFFFFFF
        LDRNE   R2, =0x55555555     ; ODD  -> R2 = 0x55555555
        LDR     R3, =RES
        STR     R2, [R3]            ; result flag stored at 0x40000000
STOP    B       STOP
NUM     DCD     0x0000001B          ; number to test (27 -> ODD)

        AREA    DATAMEM, DATA, READWRITE
RES     DCD     0
        END

Result: NUM = 0x1B (odd)  -> R1 = 1, R2 = [0x40000000] = 0x55555555
        NUM = 0x1A (even) -> R1 = 0, R2 = [0x40000000] = 0xFFFFFFFF
